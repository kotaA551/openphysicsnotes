## Differential Geometry typography

The MDX major sections are `h1` elements. The page title is a separate `h1` outside the MDX body. `ArticlePage` adds `differential-geometry-body` only for this curiosity, in every locale. Its scoped CSS renders the seven body `h1` headings at 25px (the existing site `h2` size), removes the permalink underline and inherits the neutral heading color into the link. It retains heading levels, IDs, permalink URLs and the global focus-visible outline.

The light color is `#111`. `light-dark(#111, #e5e7eb)` supplies a neutral light color when the effective document color scheme is dark. The existing site currently uses a light surface; the rule does not turn light text on merely because the operating system prefers dark mode. Other articles and the actual article title are outside this selector.

## Verification workflow

The standard prebuild regenerates `lib/discussions/manifest.json`. Search indices are generated by the existing `/search/[locale]` static routes during the full Next build. Metadata and sitemap availability use the existing article loader, so the new translations form self-canonical reciprocal ten-language clusters automatically.

```sh
node --test tests/search/*.test.mjs tests/discussions/*.test.mjs
node node_modules/typescript/bin/tsc --noEmit --incremental false
npm run build
node tests/curiosities/source-check.mjs
node --test tests/seo/metadata.test.mjs
node tests/search/generated-search-check.mjs
node tests/seo/generated-seo-check.mjs

The generated check inspects all 70 curiosity routes, including the ten Differential Geometry style scopes and unchanged Navier–Stokes editions.

## Failed attempts, resolution and remaining limitation

The first sandboxed build failed with Windows `EPERM` while creating `.next/static/chunks/app/[locale]/privacy` in the isolated checkout. The same `npm run build` was rerun through the supported per-command `require_escalated` approval reviewer and succeeded. No operating-system security setting, ACL or execution policy was changed. Dependency installation used the lockfile with `--ignore-scripts`; its network/TLS retry used Node's per-process `--use-system-ca`, not a disabled TLS check or persistent npm setting.

The first generated-curiosity DOM check exhausted Node's heap because the checker retained large KaTeX DOMs. The checker now closes each jsdom window in `finally`; the unchanged 70-page validation then passed with the normal heap limit. This was a test-harness resource issue, not a page-build failure.

Sandboxed localhost access initially returned `EACCES`. The preview server and read-only HTTP verification succeeded through per-command reviewed escalation. The review preview is bound only to `http://127.0.0.1:3104`; this is not publication. Example routes are `/ja/curiosities/black-hole-information-paradox` and `/ja/curiosities/differential-geometry`. Restart, if needed, from the isolated checkout with `node node_modules/next/dist/bin/next start --hostname 127.0.0.1 --port 3104`.

Browser visual verification remains **UNRUN**: two initialization attempts terminated the browser tool's trusted Node kernel; another attempt after reconnecting the execution environment returned `Transport closed`. Opening the preview panel also returned `Transport closed`. Static generated HTML/CSS, localhost HTTP and jsdom checks do not substitute for visual browser confirmation. Asset PNG inspection covers the illustrations only. No other scoped implementation or automated-verification blocker remains. Applying the isolated diff to the canonical repository, pushing and publishing remain subject to parent approval.
